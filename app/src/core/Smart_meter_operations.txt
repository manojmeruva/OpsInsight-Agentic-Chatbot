## SAP IS-U (Billing & Customer System)

- Sends **Remote Disconnection (RDC)** and **Remote Connect (RC)** requests to Oracle MDM  
  - Prepaid RDC: Any time, any day  
  - Postpaid RDC: Weekdays only, 07:00–12:00 PM (week starts Sunday)
- Sends **Meter Read Orders (MROs)** across ~20 billing cycles per month
- Receives final meter readings from Oracle MDM for billing

---

## Oracle MDM (Meter Data Management Hub)

### Common Responsibilities
- Receives commands from SAP
- Creates an **Activity** to track the request lifecycle
- Sends outbound communications to HES
- Waits for HES response (SLA: 45 minutes)
- Updates meter status
- Sends final response back to SAP

---

### RDC (Remote Disconnection)

- Receives RDC request from SAP
- Creates Activity
- Sends outbound to HES
- Waits for HES response (SLA: 45 minutes)

**HES Response Handling**
- If **success**:
  - Activity marked **COMPLETED**
  - Meter status updated
  - Confirmation sent to SAP
- If **failure or synchronous error**:
  - **Prepaid RDC**: Forwarded immediately to SMOC
  - **Postpaid RDC**:
    - Retry if error code qualifies
    - Up to **3 retries (maximum 4 attempts total)**
    - Retries allowed only within **07:00–12:00 PM**
    - Each retry creates a new outbound to HES
    - If no success by 12:00 PM, activity is **DISCARDED** and a negative response is sent to SAP

**Manual RDC**
- Certain postpaid reason codes are configured for manual disconnection
- These requests are sent directly to SMOC

---

### RC (Remote Connect)

- RC requests are received **24x7** from SAP
- Activity is created and outbound is sent to HES
- HES SLA: **45 minutes**

**HES Response Handling**
- If **success**:
  - Activity marked **COMPLETED**
  - Meter status updated
  - Response sent to SAP
- If **failure (any error code)**:
  - Request is forwarded to SMOC
  - Parallel retry to HES is triggered after **10 minutes**
  - Maximum HES retry count is **2**

**Retry and Finalization Logic**
- MDM waits for responses from both **HES and SMOC**
- If either system returns a positive response, the activity is finalized
- If HES responds negatively first, another retry is triggered
- If SMOC responds negatively first, MDM continues HES retries until exhausted
- No retry mechanism exists in the SMOC flow
- If no HES response within 45 minutes, HES outbound is discarded and request is forwarded to SMOC

**SMOC Flow for RC**
- SMOC SLA is **2 hours**
- SMOC provides synchronous ticket number and asynchronous final response
- If SMOC returns success:
  - Activity marked **COMPLETED**
- If SMOC returns failure:
  - Activity marked **DISCARDED**
  - Negative response sent to SAP

---

### MRO (Meter Read Orders)

- MROs are received from SAP **3 days before billing date**
- Validated using **D2-UsgTranSeeder**
  - If critical errors exist, MRO fails
- Valid MROs are created with status **CAL-DEFER**
- **CM-UTCD** batch processes reads starting the day after billing date

**Processing Outcomes**
- If valid reading received:
  - MRO marked **SENT**
  - SAP responds with **ACKRECEIVED**
- If reading is missing:
  - State set to **ISSUE-DETD**
  - **CM-MRACT** creates missing read activity
  - Request sent to SMOC
  - Read awaited from SMOC / HES / HHU
  - Retries continue until billing cycle expiry
  - Reminder sent to SMOC 2 hours before expiry
  - If still missing, MRO is **DISCARDED** and failure sent to SAP

---

## HES (Head-End System)

- Receives RC/RDC commands from MDM
- Communicates with smart meters
- Typically responds within seconds
- SLA maximum: **45 minutes**

**Failure Scenarios**
- Synchronous error (e.g., invalid meter): returned immediately
- No response: timeout triggers retry or SMOC fallback

---

## SMOC (Smart Meter Operations Center)

- Handles manual fallback for RC, RDC, and MRO
- Responses are asynchronous

**RDC via SMOC**
- Success: Activity marked **COMPLETED**
- Failure: Activity marked **DISCARDED**

**RC via SMOC**
- Ticket created
- Final success or failure returned asynchronously

**Missing Reads**
- Receives missing read requests
- Returns readings if available
- MDM retries until cycle expiry
- Final failure results in **DISCARDED** status

---

## Success Rate Metrics (Reference)

| Process | Description | Typical Success Rate |
|-------|------------|---------------------|
| RC | Remote + manual via SMOC | ~99% |
| RDC | Remote + retries + SMOC | ~90% first try, ~98% overall |
| MRO | Across retry window | ~95–96% Day 1, ~99.5% by Day 4 |
